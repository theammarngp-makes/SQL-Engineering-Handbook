# 🏅 Certifications

*Part of the [Resources Library](README.md) — [SQL Engineering Handbook](../README.md)*

Certifications don't replace a portfolio — the projects in [`projects/`](../projects/) do more for a job application than a badge does. But a recognized certification is a fast, external signal of a specific skill, and worth it once the underlying skill is already real.

---

| Certification | Issuer | Best For | Free / Paid |
|---|---|---|---|
| **Oracle Database SQL Certified Associate** | Oracle | A formally recognized, vendor-neutral-in-spirit SQL fundamentals credential | Paid (exam fee) |
| **Microsoft Certified: Azure Data Fundamentals (DP-900)** | Microsoft | Entry-level validation for the Microsoft/Azure data stack | Paid (exam fee) |
| **SnowPro Core Certification** | Snowflake | Validating Snowflake-specific warehouse knowledge for a role using it | Paid (exam fee) |
| **SQL (Basic) / SQL (Advanced) Certificates** | HackerRank | A free, fast, widely recognized signal of SQL fluency, shareable directly on LinkedIn | Free |
| **dbt Analytics Engineering Certification** | dbt Labs | Signaling dbt/analytics-engineering competency specifically | Paid (exam fee) |

> [!TIP]
> If choosing one, HackerRank's SQL certificates are the lowest-cost way to get a credible, verifiable signal while you're still building the portfolio projects that do the real convincing.
